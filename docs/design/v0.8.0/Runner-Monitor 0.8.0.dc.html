Design 0.8.0 · anbieterunabhängig

Der Monitor erkennt selbst, welche Runner auf der VM laufen (GitHub, Forgejo, Gitea, GitLab, unbekannte), zeigt, wie sicher er ist, und sagt je Fund, was zu tun ist. Grundlage ist 0.4.0; alles, was dort festgelegt ist, bleibt. Links wählen, mit ‹ › oder den Pfeiltasten blättern.

1
Einrichtung: neuer Schritt „Runner“
Code → Zugang → Runner → Anbinden → Fertig. Je Fund Dienst, Server, Version, Sicherheitsgrad, aufklappbare Begründung und eine klare Handlung.
2
Anbinden je Dienst
Ein Block je übernommenem Runner mit den Zugangsdaten, die dieser Dienst braucht, „Verbindung prüfen“ und „Überspringen“. Bei einem Runner so schlicht wie bisher.
3
Mehrere Runner: Reiter an der Runner-Spalte
Variante C. Auslastung gehört zur VM, Runner-Status, Jobs und Live-Log zum gewählten Runner. Ein Runner: keine Reiter. Wahl je Browser gemerkt.
4
„Nicht verfügbar“ ehrlich zeigen
Grundüberwachung: Dienst, Neustarts, Journal statt Schritte. Teilweise: „Schritte nicht verfügbar“, Job und Laufzeit bleiben.
5
Info › Runner und Verbindungen
Neuer Abschnitt ganz oben: Zuordnung ändern, Ignorieren, Zugangsdaten (Befehl auf der VM), „Neu erkennen“. „GitHub-Verbindung“ wird „Verbindungen“.
6
Setup-Skript zeigt die Erkennung
Tabelle „Runner auf dieser VM“, 80 Zeichen breit, ohne Farben lesbar. Auch „kein Runner gefunden“.
7
Neutrale Begriffe
„Jobs je Repository“ statt „Workflows“, „Zugangsdaten einrichten oder erneuern“, „Runner offline beim Dienst“. GitHub nur, wo es um GitHub geht.
8
Sprache: Deutsch und Englisch
Info › Darstellung › Sprache: Automatisch (Systemsprache, sonst Englisch), Deutsch, English. Alle Bildschirme übersetzt, Wörterbuch in i18n-0.8.0.js.
