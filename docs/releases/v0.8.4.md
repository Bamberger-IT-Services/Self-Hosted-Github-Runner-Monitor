# Version 0.8.4

**Stand: 15.11.2026 · veröffentlicht am 15.11.2026**

Forgejo- und Gitea-Runner, die auf Instanz-Ebene registriert sind, werden wieder zugeordnet: Die
Karte zeigt nicht mehr „Forgejo: nicht sichtbar“ ohne Jobs, auch bei forgejo-runner ab 12.7, der
keine `.runner`-Datei mehr anlegt. Handbuch dieser Version:
`https://github.com/Bamberger-IT-Services/Self-Hosted-Github-Runner-Monitor/tree/v0.8.4/docs/handbuch`

## Update
Info › Updates: erst „Jetzt prüfen“, dann „Jetzt auf 0.8.4 aktualisieren“ – oder auf der VM:
`sudo /opt/runner-monitor/aktuell/einrichten.sh aktualisieren`. Mit „Automatisch aktualisieren“
spielt der Monitor es nachts selbst ein.

## Einmalig nach dem Update
Keine Schritte nötig. Die Kennung des Runners kommt automatisch aus seiner Konfiguration (`.runner`, `runner.file` oder `server.connections`). Wer bisher den Namen beim Server als Anzeigenamen eingetragen hatte: unter Info › Runner › „Zuordnung ändern“ im neuen Feld „Name beim Server“ eintragen. Offene Dashboard-Fenster einmal neu laden.

## Was ist neu
- Forgejo/Gitea: neues Feld „Name beim Server“ unter Info › Runner › „Zuordnung ändern“ – es zählt wie der Name aus `.runner`, auch in `/admin` und den Listen der Repositories (#172)
- Erkennung: Die Registrierung wird dort gesucht, wo der Runner sie erwartet – `runner.file` aus seiner Konfiguration, auch unter anderem Dateinamen als `.runner`
- Erkennung: forgejo-runner ab 12.7 – Server und Kennung kommen aus `server.connections` der Konfiguration, der Token wird nie gelesen
- Fehlt die Registrierung, nennt die Begründung den erwarteten Ort

## Geändertes Verhalten
- Bei Forgejo und Gitea heißt der Sicherheitsgrad nur noch „sicher“, wenn UUID oder Name beim Server bekannt sind; sonst
  „wahrscheinlich – Name beim Server unbekannt – Zuordnung ändern“. Bisher genügte, dass der Server aus `runner.json` antwortete.
- Der Anzeigename zählt in `/admin/actions/runners` und den Listen der Repositories weiter nicht (wie seit 0.8.3, #152) –
  dafür gibt es jetzt „Name beim Server“.
- Bei mehreren Verbindungen in `server.connections` gilt die, deren `url` zum Server in `runner.json` passt; ohne Server dort
  lautet der Grund „mehrere Verbindungen – Server in runner.json eintragen“.

## Bekannt
- Noch nicht vollständig auf einer echten Runner-VM abgenommen; das Format von `server.connections` ist an der
  Beispielkonfiguration und dem Quelltext von forgejo-runner 12.7 bis 13.2 belegt, nicht an einer laufenden VM geprüft.
- Gitea nur nach der OpenAPI-Beschreibung, GitLab nach der offiziellen Dokumentation umgesetzt.
